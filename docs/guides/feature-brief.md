# Feature brief

Fill this in, and get the owner's yes, **before** building a feature that needs
new or changed endpoints. One page, plain words.

1. **The problem:** what the user can't do today.
2. **Who decided:** the owner, the customer, or the backend.
3. **Backend changes needed:** new endpoints or fields, each with a row in
   `docs/backend/REQUESTS.md`.
4. **The simplest version that needs no backend change:** often good enough;
   say why it is or isn't.
5. **Is the backend ready?** If not, the fake data rule applies.
